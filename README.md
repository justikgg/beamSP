# Запуск пайплайна

Все команды выполняются из корня репозитория. Разовая настройка окружения:

```bash
pip install -r requirements.txt   # зависимости
pip install -e .                  # проект как пакет (импорты config/core/entrypoint)
```

Editable-установка (`-e .`) заменяет ручную правку `sys.path`: после неё все точки
входа импортируются напрямую из любого места.

---

## Способ 1. Интерактивное меню (для демонстрации)

Пошагово спрашивает целевую величину, метод, режим синтеза и его параметры,
затем запускает оценку и печатает таблицу.

```bash
python -m entrypoint.interactive
```

Диалог:

```
Целевая величина:
  1) СП 63.13330
  2) Руководство 1978
  3) обе
Методы (через запятую, пусто — все):
  1) Линейная регрессия      ← напр. "1" или "1,2"; пусто = все
Включить синтез образцов? (Y/n)
  образцов синтеза на профиль [15]:
Сохранить результаты в results/? (y/N)
```

После прогона можно повторить с другими параметрами. Числа берутся из
[`config/settings.py`](../config/settings.py) как значения по умолчанию.

## Способ 2. Фиксированный CLI (для скриптов и воспроизводимости)

Каждый метод — свой файл-обёртка в `entrypoint/single/`; в `entrypoint/group/` —
сводные прогоны. Например:

```bash
python entrypoint/single/line_regression.py    # один метод
python entrypoint/group/baseline.py             # все линейные методы сразу
```

Флаги (общие для всех обёрток, см. [`_common.py`](_common.py)):

| Флаг | Значение | По умолчанию |
|------|----------|--------------|
| `--target {SP63,RUK78,both}` | какую целевую величину считать | `both` |
| `--no-synth` | отключить синтез образцов | синтез включён |
| `--samples N` | образцов синтеза на профиль | из `settings.SYNTH` |
| `--export` | сохранить CSV + PNG в `results/` | не сохранять |

Примеры:

```bash
# только СП63, без синтеза
python entrypoint/single/line_regression.py --target SP63 --no-synth

# обе цели, 30 синтетических образцов на профиль, с выгрузкой
python entrypoint/single/line_regression.py --samples 30 --export
```

## Способ 4. Собранный бинарный файл (демо без Python)

Однофайловый исполняемый файл GUI с зашитыми данными и зависимостями — для показа
на машине, где не развёрнуто окружение. Публикуется автоматически в
[GitHub Releases](../../releases) при каждом теге `v*`: `beam-gui-windows-x64.exe`
для Windows, `beam-gui-linux-x64` для Linux. Запуск двойным кликом или из
консоли — интерфейс тот же, что и в Способе 3.

Собрать локально (нужны `requirements-build.txt` и `requirements-gui.txt`):

```bash
pip install -r requirements.txt -r requirements-build.txt -r requirements-gui.txt
pip install -e . --no-deps
pyinstaller beam_gui.spec
```

Результат — `dist/beam_gui.exe` (Windows) / `dist/beam_gui` (Linux). Экспорт
пишется в папку `results/` рядом с исполняемым файлом.

> Бинарный файл и папки `build/`, `dist/` не коммитятся (см. `.gitignore`) — собирается
> локально из спека или скачивается из релиза.

## Результат

- Таблица `метод × метрики` по каждой целевой величине печатается в консоль.
- С `--export` / ответом «да» в меню: `results/metrics_<цель>_<время>.csv` и
  `results/plots_<цель>_<время>.png` (scatter Qэксп/Qпред + сравнение RMSE).

Ключевые метрики: `Qexp/Qpred_mean` (в идеале ≈ 1) и `CV`
`MAE`/`RMSE`/`R2` — для полноты. `overfit` = `R2_train − R2(LOGO)`
показывает переобучение.
## Произвольные датасеты и признаки

beamSP работает с runtime `DatasetSchema`: количество, имена и порядок признаков,
цели и определение профиля берутся из текущего mapping. Старый
`config/data.xlsx` открывается автоматически через legacy adapter; привычные
методы, цели, синтез и метрики сохранены. `settings.FEATURES/TARGETS` оставлены
только как совместимые legacy aliases; runner, GUI, модели и tools их не читают.

Для нового файла используйте `.csv` (UTF-8, разделитель — запятая) или `.xlsx`
(первый лист). Первая строка должна содержать уникальные непустые заголовки:

```csv
profile_id,H,s,R,E,tf,bf,Iy,A,density,Q_SP,Q_RUK
p1,150,6,30,60000,8,100,1500000,2100,1900,21.6,19.6
p1,150,6,30,60000,9,100,1600000,2200,1900,23.1,20.9
p2,200,10,30,60000,12,140,5000000,4200,1900,48,43.12
p2,200,10,30,60000,13,140,5400000,4300,1900,50,45
```

Готовые примеры с девятью новыми признаками `x1…x9`, двумя целями и четырьмя
группами: [CSV](examples/dynamic.csv), [Excel](examples/dynamic.xlsx),
[mapping](examples/dynamic.beamsp.json).

В GUI (`python -m entrypoint.gui`):

1. В блоке «Датасет» нажмите «Загрузить датасет».
2. Проверьте роли колонок: `Feature`, `Target`, `Group`, `Metadata` или `Ignore`.
   `Use` включает/выключает колонку. X состоит только из включённых Feature.
   Для числовых входов/целей выберите `Type=numeric`; двоичные значения можно
   пометить `binary`. Для материала применяется автоматическое кодирование,
   описанное ниже; остальные категории требуют отдельной стратегии.
3. Выберите одну Group, например `profile_id`. Если её нет, отметьте набор
   `Profile key`, определяющий профиль. Target нельзя использовать как ключ.
   Явная Group имеет приоритет. Для LOGO нужны минимум две реальные группы.
4. При необходимости укажите единицы и `Noise ±` по именам признаков.
   Нулевой/незаданный шум не меняет признак. Targets, Group и metadata защищены.
   Синтетические строки сохраняют группу родителя; весь held-out профиль,
   включая его синтетические строки, исключается из train.
5. «Применить роли» проверяет данные. Ошибки NaN/inf, числового преобразования
   и ролей отображаются без удаления строк или подстановки значений.
6. Выберите цели/методы и нажмите «Запустить». Фиксация степеней bio-моделей
   автоматически показывает выбранные признаки. `Formula` разрешает признак
   в степенной модели; `Monotonic` задаёт направление ограничения PINN.
7. «Сохранить mapping» записывает рядом с файлом `имя.beamsp.json`. При
   следующем открытии он загружается автоматически. Порядок X, роли, единицы,
   шум и ограничения сохраняются. Обычные дополнительные колонки, появившиеся
   после сохранения mapping, видны как Ignore: назначьте им Feature и сохраните
   снова. Распознанный `is_steel` автоматически добавляется как бинарный Feature.

Чтобы добавить новый feature **без изменения Python-кода**, добавьте числовую
колонку в CSV/XLSX, откройте файл, назначьте ей Feature и нажмите «Запустить».
Имена `H/s/R/E` не обязательны. Обычные модели получают X нужной ширины, а
формульные методы получают реальные имена входов.

При отсутствии mapping загрузчик предлагает Group для `profile_id/group_id/group`,
Target для имён с префиксом `target/Q_/Qдв_`, Metadata для `id`, `shifr`,
`шифр`, `is_synth` и имён с суффиксом `_id`, Feature для остальных числовых
колонок, Ignore для остальных. Это предложение нужно проверить: смысл
произвольного названия колонки невозможно определить автоматически. Если
цель называется иначе, назначьте её Target вручную или передайте mapping/CLI.

### Автоматическое использование материала

Для нового CSV/XLSX достаточно текстовой колонки `material`, `material_type`,
«Материал», «Тип материала», «Материал двутавра» или «Тип материала двутавра».
Регистр и лишние пробелы в названиях и значениях не влияют на распознавание.
Загрузчик по имени колонки создаёт дополнительный вход:

| Значение материала | is_steel |
|---|---|
| сталь / стальной / steel | 1 |
| композит / композитный / composite | 0 |

Также допускается уже заданный код 1/0. `is_steel` автоматически получает
`Role=Feature`, `Use=true`, `Type=binary` и входит в X обычных моделей.
Текстовая колонка сохраняется как Metadata. Для степенных bio-моделей у нового
признака отключён Formula, поскольку они не поддерживают `log(0)`; это
не отключает его для остальных моделей. Синтез бинарный признак не изменяет.

Готовый файл: [examples/material.csv](examples/material.csv). В нём вручную
добавлять `is_steel` не нужно:

```bash
python -m entrypoint.single.line_regression --data examples/material.csv --no-synth
```

Если сохранённый mapping ещё не содержит `is_steel`, признак автоматически
добавляется в схему. Если пользователь ранее явно отключил его через Use или
Ignore, эта настройка сохраняется. Если числовой `is_steel` уже присутствует,
он проверяется на значения 0/1 и согласованность с материалом, без перезаписи
противоречивых данных. Неизвестный материал или пропуск вызывает понятную ошибку;
он не превращается автоматически в «композит». При нескольких колонках
материала нужно оставить один источник преобразования.

Источник сохраняется в `derived_from` схемы и metadata результатов.
Преобразование использует фиксированное правило и не обучается на данных.
Колонка материала, назначенная Target или Group, автоматически не кодируется
в Feature. Изменение роли источника уже созданного признака также проверяется,
чтобы не передавать Target/Group в X через производный `is_steel`.

### CLI и использование без GUI

Все single/group entrypoints, интерактивное меню и `tools/*` поддерживают
`--data`, `--schema`, `--features`, `--targets`, `--group`, `--profile-cols`.
`--target` выбирает ключ цели из схемы; `both` означает все цели.

```bash
# mapping из examples/dynamic.beamsp.json читается автоматически
python -m entrypoint.group.baseline --data examples/dynamic.csv --target target_a --no-synth

# Явное назначение произвольных имён, без sidecar
python -m entrypoint.single.line_regression --data my.csv \
  --features H,s,tf,bf,Iy --targets Q_SP,Q_RUK --group profile_id --no-synth

python -m tools.tune_model --data examples/dynamic.csv --model ridge \
  --target target_a --grid alpha=1,10 --no-synth
```

```python
from core.data.loader import load_dataset_bundle
from core.data.schema import DatasetSchema
from core.evaluation.runner import run

schema = DatasetSchema.from_mapping(
    columns=["profile_id", "x1", "x2", "tf", "target_a"],
    features=["x1", "x2", "tf"], targets=["target_a"],
    group_column="profile_id",
)
schema.spec("tf").synthetic_noise = 0.2
schema.spec("tf").unit = "мм"
dataset = load_dataset_bundle("my.csv", schema=schema)
result = run(["linear", "ridge", "gbr"], dataset=dataset, seed=1337,
             synth_cfg={"enabled": True, "samples_per_profile": 2})
print(result.metrics["target_a"])
```

Историческое имя `samples_per_profile` сохранено для совместимости: фактически
это число дополнительных копий **каждой исходной строки**. Поэтому старый
режим даёт 18 реальных + 18 × 15 = 270 синтетических строк.

При экспорте вместе с CSV/PNG записывается `metadata_<время>.json`: путь/имя
датасета, упорядоченные признаки, targets, Group/ключи профиля, количества строк
и групп, seed, schema, настройки синтеза, фиксированные степени и формулы.
Единицы осей берутся из target schema; для нового файла кН не предполагаются.
`R2_train` оценивает финальную модель, обученную на всей выборке, а `R2` — LOGO.
`tools/importances.py` считает permutation importance на обучающих реальных
строках финальной модели; это не независимая оценка обобщения.

### Совместимость методов и ограничения

Все 19 зарегистрированных методов принимают произвольную ширину X; ограничения
касаются значений и размера train fold:

| Методы | Ограничения |
|---|---|
| Linear/Ridge/Lasso/ElasticNet, GBR/SVR/GPR, MLP, RL | Числовые конечные features и targets |
| KNN | В каждом train fold должно быть хотя бы `n_neighbors` строк; default = 55. На маленьком датасете выберите меньше через конструктор/`tools.tune_knn` либо используйте синтез |
| bio GA/DE/PSO/CMA-ES, Log-Linear LS, LS + TRF | Разрешённые в степенной формуле features и target строго положительны. Неположительные входы вызывают понятную ошибку; автоматического исключения нет |
| symreg | Защищённые `sqrt/log/div` gplearn; названия берутся из runtime schema |
| bayes_symreg | Как раньше: `sqrt(abs(x))`, `log(abs(x)+1e-9)`; для binary только линейные термы и взаимодействия |
| PINN | Сохраняет физический штраф Q ≥ 0 и требует неотрицательный target. Монотонность задаётся schema; для legacy H/s/R — возрастание, для новых признаков ограничения по умолчанию отсутствуют |
| Старые fixed SP63/RUK78/no-E presets | Предметные формулы требуют названных в preset физических признаков. При их отсутствии — ошибка; общий bio_* работает с любыми именами |

Legacy `is_steel` явно исключён из степенной формулы через schema, как ранее,
но остаётся входом остальных моделей. StandardScaler/Pipeline, преобразования
цели, ARD-нормировка и диапазоны PINN обучаются заново внутри каждого train fold.

Для нового метода достаточно унаследовать `BaseModel`, реализовать `fit/predict`,
задать `name/group` и вызвать `register_model(MyModel)` (можно как декоратор) до
создания окна. Он появится в списке GUI.

## Log-Linear LS и LS + TRF

В группу вывода формулы добавлены два метода из `from_partner`:

- `log_linear_ls`: ограниченный МНК в логарифмах (`lsq_linear`, BVLS).
- `log_linear_trf`: старт из LS и уточнение ошибки в исходных единицах
  (`least_squares`, TRF, аналитический якобиан).

Они доступны в GUI и интерактивном меню. Отдельные команды:

```bash
python -m entrypoint.single.log_linear_ls --target both --export
python -m entrypoint.single.log_linear_trf --target both --export
# Искусственный Excel с новым признаком x_extra и шестью группами:
python -m entrypoint.single.log_linear_ls --data examples/power_law_extra.xlsx --no-synth
```

Оба метода получают порядок признаков из runtime schema. Чтобы исключить
неположительный или неподходящий столбец из степенной формулы, выключите
`Formula` в GUI или задайте `formula_allowed: false` в mapping; остальные
модели продолжат получать его как Feature. Неположительные цели запрещены.
После изменения набора входов обязательно повторное обучение.

В `metadata_*.json` сохраняются точные коэффициенты по каждой цели и каждому
LOGO fold, включённые/исключённые признаки, ранг логарифмической матрицы,
диагностика сходимости, дата, seed и версии среды. Округлённые формулы нужны
для отображения; точные расчёты используют коэффициенты из metadata.

В эксперименте партнёра TRF ухудшил LOGO на обеих целях, хотя уменьшил
обучающую ошибку; он остаётся экспериментальной альтернативой. Полное
описание интеграции, проверок и текущих результатов:
[docs/ls_trf_integration.md](docs/ls_trf_integration.md).
