`from_partner/Инструкция_для_напарника.md` и технических инструкций архива.
Исходные материалы партнёра сохранены без изменений. Резервная копия
затронутых каталогов до интеграции:

## Подключённые методы

`core/models/baseline/log_linear_ls.py`: `LogLinearLSModel`, ключ
`log_linear_ls`. Решается ограниченная линейная задача для
`[ln(A), p1, …, pk]` через `scipy.optimize.lsq_linear(method="bvls",
lsq_solver="exact", tol=1e-10)`. Ограничения взяты из `PowerLawForm`:
`ln(A) ∈ [-20, 20]`, свободные степени `[-5, 5]`. Вклад фиксированных
степеней вычитается из логарифмов цели до решения задачи.

`core/models/baseline/log_linear_trf.py`: `LogLinearTRFModel`, ключ
`log_linear_trf`. Начальные коэффициенты — результат LS; затем TRF
минимизирует сумму квадратов ошибок в исходных единицах цели. Сохранены
аналитический якобиан, ограничения, настройки и проверки невозрастания SSE
партнёра. Допустимое решение при лимите итераций сохраняется с
`diagnostics.success=false` и сообщением о недостигнутой сходимости.

В реестр и русские подписи добавлены только новые записи; существующие
алгоритмы и их настройки не заменялись. GUI и интерактивное меню получают
новые методы из реестра автоматически. Отдельные точки входа:

```bash
python -m entrypoint.single.log_linear_ls --target both --export
python -m entrypoint.single.log_linear_trf --target both --export
python -m entrypoint.single.log_linear_ls --target SP63 --no-synth
```

SciPy добавлен как прямая зависимость в `pyproject.toml` и `requirements.txt`.
Проверено в собственном `venv`: Python 3.12.3, NumPy 2.5.0, SciPy 1.18.1,
pandas 3.0.3, scikit-learn 1.5.2. Окружение из архива не копировалось.

## Адаптация к текущему проекту

Текущая версия уже содержит загрузчик CSV/XLSX с заголовками,
`DatasetSchema`, редактор ролей GUI и группировку независимо от X.
Поэтому старые loader/runner/GUI из reference архива не переносились.
Модели подключены к существующим `configure_features`, `validate_input`
и свойству `ColumnSpec.formula_allowed`.

В экспериментальной копии партнёра неположительные столбцы исключались
автоматически, а цели ограничивались снизу числом `1e-9`. В текущем проекте
приняты другие правила: все выбранные числовые значения должны быть
конечными; разрешённые степенные признаки и цели строго положительны.
LS/TRF следуют этим правилам, не меняют цели и не отбирают признаки по
составу отдельного fold. Некорректный признак вызывает ошибку с именем
столбца. Для явного исключения выключите `Formula` в GUI или задайте
`formula_allowed: false` в JSON mapping. Legacy `is_steel` уже исключён
этим способом и остаётся входом остальных моделей.

Сохранены все 29 математических проверок партнёра с адаптацией к явным
исключениям и строгой положительности целей. Добавлены интеграционные
приёмочные проверки и запуск новых методов через GUI.

Для фиксации степеней через Python поддерживаются индексы исходных
столбцов и имена:

```python
from core.models.baseline.log_linear_ls import LogLinearLSModel

names = dataset.schema.features
model = LogLinearLSModel(fixed_exponents={"x_extra": 0.4})
model.configure_features(names, dataset.schema)
model.fit(dataset.frame[names].to_numpy(float), dataset.frame["Q_test"].to_numpy(float))
print(model.formula(names))
```

Секция фиксации степеней GUI сохраняет своё прежнее назначение для bio-методов.

## Новые поля и физические профили

1. Новый файл: CSV с запятыми или XLSX с уникальными заголовками первой строки.
   Старый многострочный `config/data.xlsx` по-прежнему использует legacy adapter.
2. В GUI загрузите файл, назначьте `x_extra` роль Feature. Все цели, в том
   числе невыбранная цель, должны иметь роль Target. Материал и служебные
   поля остаются Metadata/Ignore, профиль — Group или отдельные Profile key.
3. Если mapping уже сохранён, обычные новые столбцы первоначально получают
   Ignore: выберите Feature и сохраните mapping снова. Произвольный числовой
   столбец нельзя надёжно классифицировать без участия пользователя.
4. Автоопределение теперь защищает также числовые `id`, `shifr`, `шифр`,
   `is_synth` и имена с суффиксом `_id` от случайного попадания в X.
5. Единицы задаются в schema и сохраняются в результатах. Категории требуют
   отдельного кодирования; существующее преобразование материала в
   `is_steel` сохранено. Пропуски/NaN/inf не удаляются и не заполняются молча.
6. `schema.features` задаёт один порядок для X, обучения и имён формулы.
   После добавления признака повторите fit; старые коэффициенты не подходят
   матрице другой ширины. При прогнозе используйте сохранённый порядок.

Физические профили определяются Group или `grouping_columns`, независимо
от признаков модели. Для legacy сохранены ключи `is_steel,H,s,R,E` и шесть
групп. Меняющийся внутри профиля `x_extra` их не дробит. При синтезе группа
фиксируется до шума; весь отложенный профиль со своими копиями исключается
из обучения. Метрики считаются только на реальных отложенных строках.

Матрица `[1, ln(X_free)]` проверяется на ранг при каждом fit. Недостаточный
ранг не запрещает прогноз, но отражается в metadata и сообщениях CLI/GUI:
свободные показатели нельзя восстановить однозначно. Для исходных реальных
данных ранг 5 при 6 параметрах; шум синтеза поднимает его до 6. Это не
заменяет физические наблюдения и не доказывает идентифицируемость
инженерной зависимости на реальных данных.

## Сохранение результатов

Штатный экспорт сохраняет CSV метрик, PNG и `metadata_*.json`. Новые поля:

- `created_at` — время UTC с часовым поясом; `environment` — реальные версии.
- `per_target[цель].models[метод]` — точные `A`, `log_a`, степени по именам,
  параметры и границы, порядок всех/использованных признаков, исключения,
  диагностика LS/TRF и аналогичные данные каждого LOGO fold.
- Для TRF доступны начальная/финальная SSE, число вызовов, сходимость и
  настройки обоих решателей. Для обоих методов — ранг, число параметров,
  число обусловленности и сообщения о неоднозначности показателей.

Существующие поля schema, единиц, seed, целей, групп и синтеза сохранены.
Отображаемая формула округлена; для точного расчёта используйте `log_a` и
`exponents` в порядке `used_feature_columns`:

```python
prediction = np.exp(np.clip(log_a + np.log(X_used) @ powers, -50, 50))
```

## Проверка и полученные результаты

До изменений прошли 42 существующих теста. После интеграции проходят 79,
включая 29 математических проверок партнёра, полные GUI/CLI проверки,
legacy regression fixtures, Excel с `x_extra`, неизменность групп,
точное восстановление показателя 0.4 при разной ширине/перестановке X,
повторное обучение и воспроизведение LOGO-прогнозов из экспортированных
коэффициентов каждого fold.

```bash
QT_QPA_PLATFORM=offscreen MPLCONFIGDIR=/tmp/beamsp-mpl \
  python -m unittest discover -s tests -v
```

Сохранённые прогоны находятся в `reports/ls_trf_integration/`.
Seed 1337; 18 реальных строк, шесть профилей; при синтезе 15 копий на
исходную строку (270), шум — штатный `config.settings.SYNTH`.
RMSE LOGO, кН:

| Метод | СП63, синтез | РУК78, синтез | СП63, без синтеза | РУК78, без синтеза |
|---|---:|---:|---:|---:|
| DE | 1.510823 | 0.814288 | 0.210772 | 0.511445 |
| Log-Linear LS | 1.689377 | 1.197454 | 0.210368 | 0.513685 |
| LS + TRF | 6.474775 | 6.225771 | 0.142744 | 0.265728 |

LS/TRF при штатном синтезе воспроизводят числа партнёра до указанной им
точности. Текущий DE, особенно РУК78, отличается от переданного измерения
DE=3.327; исходный код DE сохранён, новое измерение приведено отдельно.
Исторические отчёты партнёра не переписаны и превосходство LS над DE на
этих данных не утверждается. Повторный временной бенчмарк здесь не проводился.

Отрицательный результат TRF при синтезе подтверждён: уменьшение обучающей
SSE сопровождается ухудшением LOGO на обеих целях. Без синтеза здесь
получается иной результат, при недостаточном ранге исходной матрицы.
Техническая сходимость не заменяет проверку обобщения.

Отдельный искусственный пример: `examples/power_law_extra.xlsx` и mapping
рядом с ним, 60 строк/шесть групп, две тестовые цели:

```text
Q_test  = 2.5 * x1^0.8  * x2^-0.3 * x_extra^0.4
Q_other = 1.8 * x1^-0.2 * x2^0.6  * x_extra^-0.5
```

Оба метода восстанавливают 0.4 и -0.5 с численной точностью; RMSE порядка
`1e-15`. Это проверка алгоритмов, а не новая инженерная формула.

```bash
python -m entrypoint.single.log_linear_ls --data examples/power_law_extra.xlsx --no-synth
python -m entrypoint.single.log_linear_trf --data examples/power_law_extra.xlsx --no-synth
```
